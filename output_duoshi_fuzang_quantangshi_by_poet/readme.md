# 多识模型《白氏六帖》傅藏本 × 《全唐诗》诗人互文候选统计

本目录保存《白氏六帖事类集》（傅藏本）与《全唐诗》之间的诗人层互文候选统计结果。数据来自本地输出目录 `output_duoshi_fuzang_quantangshi_by_poet`，采用“类书文本 3-gram 候选召回 + 多识向量精排”的口径。

## 数据来源

- 类书文本：《白氏六帖事类集》（傅藏本）结构化 JSON。
- 类书向量：复用 `output_duoshi_fuzang_baijuyi_v5_note_type_35340` 中的 `note_type_aware_channels` 类书侧向量。
- 诗歌文本：`Ethan-do0707/tang_poetry` 仓库的 `tang_poetry.sql`。
- 《全唐诗》来源提交：`3f3039bbeb18111247e41ec67b62042c936da46e`。

## 数据规模

- 类书记录：`35,340` 条
- 《全唐诗》可用诗作：`41,734` 首
- 归一诗人：`2,492` 位
- 全部句级单位：`437,491` 条
- 3-gram 候选句级单位：`11,275` 条
- 候选召回比例：约 `2.58%`
- 候选精排耗时：约 `872.46` 秒

## 方法说明

本轮没有构造《全唐诗》全部句级单位与《白氏六帖》全部类书记录之间的穷举语义矩阵。原因是 `437,491 × 35,340` 的全量句级比对在当前 CPU 环境下成本较高，float16 矩阵估算约 `28.80 GB`。

实际流程为：

1. 从类书侧 `词条 / 解析注文 / 注文` 中构造 3-gram 候选片段集合。
2. 在《全唐诗》全部句级单位中召回含候选片段的句子。
3. 对候选句子使用多识模型编码。
4. 将候选句向量与 `35,340` 条类书侧向量做 best1 精排。
5. 按诗人汇总句级高值、诗级高值、最高相似度、平均相似度与关联部类。

因此，本目录更适合作为“显性词语、固定辞式、礼制公式、共同典源线索”的高精度候选表，不宜直接表述为《全唐诗》全量语义互文分布。

## 阈值口径

阈值采用候选集内部经验分位：

- 句级 `p90 = 0.741651`
- 句级 `p95 = 0.772558`
- 诗级由句级 best1 汇总，`p90 = 0.751183`
- 诗级由句级 best1 汇总，`p95 = 0.783411`

## 主要输出

- `白氏六帖_全唐诗_诗人互文统计.xlsx`：综合工作簿，含诗人汇总、诗人部类高值、句级代表样本、诗级代表样本和说明。
- `白氏六帖_全唐诗_诗人互文统计报告.md`：结果报告。
- `白氏六帖_全唐诗_诗人互文统计.csv`：诗人层汇总表。
- `白氏六帖_全唐诗_诗人部类高值统计.csv`：诗人与类书部类的高值关联统计。
- `白氏六帖_全唐诗_句级代表样本.csv`：句级代表样本。
- `白氏六帖_全唐诗_诗级代表样本.csv`：诗级代表样本。
- `全唐诗_line_best1.csv`：候选句级单位 best1 结果。
- `全唐诗_poem_from_line_best1.csv`：由句级 best1 汇总得到的诗级结果。
- `column_index_全唐诗_*.csv`：诗级、句级与候选句级索引。
- `quantangshi_poems.jsonl`：从 SQL 转换出的《全唐诗》诗作 JSONL。
- `run_summary.json`、`count_summary.json`、`tang_poetry_source_manifest.json`：运行摘要、计数摘要与来源说明。
- `large_files_manifest.json`：大文件与 Git LFS 说明。

## 注意事项

- 本结果用于互文候选发现，不等同于自动判定直接取材关系。
- 高比率小样本诗人需要加最低诗数或最低句数门槛后再解释。
- 若论文需要“全量语义互文”表述，应另行运行全量句级语义检索或 ANN 近似检索。
- 《全唐诗》SQL 源数据中存在编码异常，本轮已按可逆乱码修复策略转为 UTF-8 文本；诗人名中的尾随数字已用于归一化分组。
